# 从零学习 RAG：新版 12 步教程

这套教程面向第一次学习 RAG 的读者。目标是亲手完成：**读取自己的文档 → 检索相关原文 → 在 Unity 中根据资料回答问题并显示来源**。

先跑通一条简单流程，再解释每个模块为什么存在。代码集中在必需功能上，保留会影响数据正确性的检查，不加入索引版本发布、多轮聊天或复杂故障处理。

## 先读这几条

1. 本目录 `new_step` 只放教程。示例代码是在你学习时手动创建的，不会因阅读 Markdown 自动运行。
2. 所有项目路径都以 `C:\Users\qqcom\PycharmProjects\Rag` 为根目录。Python 代码放在 `backend`，不要建成 `new_step/backend`。
3. 这是新的完整路线。旧 `steps` 和你已有源码仍然保留；开始手敲前保存自己的代码，不要将新旧章节混用。
4. 按 step1 → step12 阅读。每篇先看目标，完成运行示例，再读解释、做小实验和验收。
5. “新建”表示创建文件；“更新”提供该阶段完整内容供对照，已经写过的内容不用重复定义。
6. 文件代码块只复制内部内容，不复制围栏和 `<!-- file: ... -->` 标记。PowerShell 命令写在终端，不能写进 Python 文件。
7. 后续配置扩展时，样例 `.env.example` 与本机 `.env` 都要对照更新。Unity 本机 JSON 配置到第 10 篇才出现。
8. 向量分数、下载速度和聊天回答因环境而异，示例用于理解结构，不保证逐字一致。

## 最终系统是什么样的

```text
准备资料（资料变更后手动运行一次）
TXT / Markdown / JSON
    → loader
    → splitter
    → BGE-M3
    → Qdrant 中的固定集合 rag_tutorial

回答问题（每次提问）
Unity 输入完整问题
    → FastAPI /retrieve
    → BGE-M3 编码问题
    → Qdrant 找到相关原文
    → Unity 组织“问题 + 原文”
    → DeepSeek 生成回答
    → Unity 显示回答和本轮检索来源
```

Python 负责找资料，Unity 负责交互和调用聊天接口。BGE-M3 不生成答案；DeepSeek 不负责保存向量。文档检索在本机，聊天调用使用网络，选中的资料和问题会发给聊天服务。

## 这版的学习约定

- Windows、PowerShell、Python 3.11；沿用已有虚拟环境，不自动重建。
- 模型以 CPU 为学习基线，先理解流程，GPU 优化不作为完成条件。
- Unity 使用现有教学版本 2022.3.62f3，单独创建新工程。
- 固定一个正式知识库集合，更新前停止查询，导入失败后重新运行。不会自动保留可回滚版本。
- 每轮输入完整问题；没有聊天历史、代词追问补全或主动取消按钮。
- 发送期间禁用发送；保留超时、失败提示和退出场景时的清理。
- 不做联网搜索、PDF/OCR、重排序、语音或数字人接入。

例如问“图书馆星期天开门吗”，不要依赖上一轮问题再问“它呢”。这是当前功能范围，不是模型自动记忆失效。

## 为什么这么设计

你首先需要理解一条资料怎样变成答案依据。固定集合和单轮问答能减少状态管理；分阶段安装和配置能减少同时遇到的问题。来源、token 上限、非空输入以及资源释放仍保留，因为它们直接关系到检索结果和程序能否正确运行。

这一版增加解释和操作细节，但尽量不增加业务代码。读懂一个小流程之后再运行，比一次抄下完整工程更适合建立理解。

## 阅读时怎样判断自己真的学会了

每篇完成后尝试回答：

- 这一篇接收什么，输出什么？
- 输出交给哪一个模块？
- 删除这一篇的核心逻辑，后面哪一步会失效？
- 我刚刚运行的结果证明了什么，还有什么没证明？

例如数据库能查出人工向量，只证明数据库存取正常，不能证明 BGE-M3 检索准确；Hit@5 较高，也不能直接证明聊天答案正确。
